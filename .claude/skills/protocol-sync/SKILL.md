# Protocol sync

The framework owns the remote debug protocol. Its spec is `DEBUG_PROTOCOL.md` in the framework repository, and its test vectors are generated by `FlixelDebugProtocolTest` into `flixelgdx-test/src/test/resources/org/flixelgdx/debug/remote/fixtures/`. This repository keeps a copy of those fixtures in `tests/FlixelDebugger.Protocol.Tests/Fixtures/`. The copy must never be edited by hand.

## Steps

1. **Locate the framework.** Use `../flixelgdx`. If `$ARGUMENTS` names a branch or commit, make sure that checkout is on it, without disturbing uncommitted work there. Ask if it is on something else.
2. **See what changed.** Diff the framework's fixture folder against this repository's copy (`diff -r`), and read the framework's `git log -p -- DEBUG_PROTOCOL.md` since the last sync. List added, removed, and changed messages, feeds, actions, widget types, and value kinds, and any protocol version bump.
3. **Re-copy the fixtures.** Replace `tests/FlixelDebugger.Protocol.Tests/Fixtures/` with the framework's folder, including its `README.md`.
4. **Update the C# side.** In `src/FlixelDebugger.Protocol`, update the message types, readers, and writers (`MessageType`, `MessageReader`, `MessageWriter`, `MessageDecoder`, `Feeds/`, `Actions/`, `Ui/`) to match the spec. Keep the rules from `AGENTS.md`: unknown messages, panels, and actions decode to their `Unknown*` types instead of throwing, and Protocol stays free of Core and UI dependencies.
5. **Add tests** for each new fixture: decode it and assert the values listed in the fixture `README.md`, then encode the same values and compare bytes.
6. **Update Core and App** only where the change needs it (a new feed or widget may need a view). Use the `new-widget-type` skill for new widget types.
7. **Run checks:** `dotnet build`, `dotnet test`, and `dotnet format --verify-no-changes`.

Report the protocol changes found, the files updated, the test results, and anything in the spec that was ambiguous.
